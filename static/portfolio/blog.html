RAG 检索2026-10-15

SQLite FTS5 中文二元分词：实现与踩坑

做灵犀 RAG 智库时，我选了一条「先 FTS5、后向量」的渐进路线：不引入向量库，用 SQLite 内置的全文检索先把知识库跑起来。好处是零运维、单文件部署；代价是得自己解决中文分词。

坑一：默认分词器对中文基本失效

FTS5 的 unicode61 分词器按 Unicode 类别切分，中文一串汉字会被当成一个「词」。「企业经营分析」存进去，用户搜「经营分析」——匹配不上，因为整串才算一个 token。搜单个字又能匹配到一堆噪音。

坑二：查询词和索引词切分方式不一致

就算入库时切了词，查询时如果按用户原话匹配，同样对不齐。必须在索引和查询两侧用同一套切分逻辑。

解法：二元分词 + 查询侧双侧展开

思路很直白：中文按两个字一组切（二元），长词全覆盖；查询时同样切二元，并且对查询串做「单侧 + 双侧」展开，兼顾二字词与单字场景。

# 索引侧：二元切分（简化示意）
def bigrams(text):
    text = re.sub(r"\s+", "", text)
    return [text[i:i+2] for i in range(len(text) - 1)]

# 「企业经营分析」→ ["企业", "业经", "经营", "营分", "分析"]

落地后中文检索命中率显著提升，答案又能强制附带原文引用——幻觉有据可查，这才是我敢把 RAG 系统拿给面试官演示的底气。局限也说清楚：超长文档分块仍有上下文丢失，多模态文件暂不支持，这些写在作品集项目卡的「已知局限」里，不藏着。

Agent 编排2026-10-12

LangGraph 多 Agent：子代理上下文隔离实践

在 CEO→CTO→CODER 多 Agent demo 系列里踩得最深的坑，是子代理的「上下文隔离」——不是把对话转发给子代理这么简单，得想清楚三件事：状态怎么传、上下文怎么切、中断怎么恢复。

一、状态传递：共享图状态，而非共享全部历史

LangGraph 的图状态是全图可见的，如果子代理把中间思考全部写回共享状态，父 Agent 的上下文会被瞬间污染。实践下来最稳的做法是：子代理只把结构化结论写回（计划、代码、错误摘要），过程数据留在子图内部。

二、上下文隔离：子图 + 独立消息通道

子代理跑在子图里，拥有自己的消息列表；父 Agent 只看到「派了什么任务、拿回什么结果」。这样 CODER 改十轮代码的中间过程，不会把 CEO 的决策上下文冲爆。

三、HITL 中断恢复：检查点是生命线

人工介入（HITL Interrupt）时流程停在等审批节点，恢复后要继续跑——靠检查点持久化整图状态。我把它和会话持久化放在一起设计：刷新页面不丢上下文，不是前端缓存，是图状态可恢复。

这套方法的验收标准很朴素：demo 08-17 每个都能独立跑通、中断后能恢复、子代理爆掉不影响主图。能做到这三点，「多 Agent」才从 PPT 变成系统。

Text2SQL2026-10-10

Text2SQL 生产环境常见坑点与校验策略

问数 ChatBI 的 12 节点 LangGraph Agent 里，真正决定「敢不敢上线」的不是生成节点，是校验节点。把踩过的坑按出现频率排个序：

坑 1：模型不知道数据库里有什么

全量 schema 塞进 prompt，表一多就超长且干扰注意力。解法是 Schema Linking 前置：用 Qdrant + Elasticsearch 双索引 + bge embedding 把表名、字段名、注释向量化，提问时先检索最相关的表结构再生成。

坑 2：SQL 能跑但结果是错的

找错关联字段、聚合维度选错，比语法错误更隐蔽。解法：校验节点检查关联表是否都经过 linking 命中，未命中字段要求重生成或转澄清。

坑 3：危险操作没有闸门

模型偶尔会「贴心」地加上 UPDATE / DELETE 或漏掉 LIMIT。四道静态校验兜底：

  1. 只允许 SELECT 开头，拒绝任何写操作；
  2. 强制 LIMIT 存在且不超过阈值，防全表拉爆；
  3. 关联表必须全部出现在 linking 命中集里；
  4. 语法层预解析，明显残缺直接打回。

坑 4：等待体验差

解法是 FastAPI SSE 流式：总结阶段按 token 推送，SQL 和引用随结果一起返回——用户能核对「这个数是怎么算出来的」，信任感比正确率数字更值钱。

边界也摆明：三表以上复杂关联仍会出错，歧义问句需要澄清轮次。这些都是作品集项目卡「已知局限」里的原话。

工程降级2026-10-08

LLM 应用多链路故障降级方案设计

LLM 项目的「生产可用」，一半是功能，一半是降级。我在融界工作台和罗盘医药里把降级当成一类正常输入来设计，而不是异常处理补丁。

为什么必须设计降级

Key 会过期（我自己的腾讯套餐就过期 403 过）、接口会限流（429）、服务会挂（502）、网络会抖。任何一环出问题，如果没有降级，用户看到的就是白屏或报错——演示现场出这种事，比没有 AI 功能更糟。

三级降级架构

  1. 主链路：SiliconFlow（Qwen 系），日常走这条；
  2. 备用链路：阿里百炼，主链路超时 / 报错自动切；
  3. 演示模式：两条都不可用，切规则引擎兜底——界面、交互、数据流完全一致，只是回答由本地规则生成。

关键实现细节

  • 健康探测：启动即探测 LLM 可用性，徽章实时显示「LLM 已连接 / 演示模式」，不把探测中的中间态暴露给用户；
  • 超时预算：单次调用超时短于用户可感知阈值，失败立刻降级而不是让用户干等；
  • 降级可见：罗盘里 RAGFlow 挂断时会标注「知识库降级」，用户知情不等于体验降级；
  • 状态一致：三种模式共用同一套前端交互，切换对用户无感。

这套架构的回报很直接：不管 Key 有没有效、网络通不通，演示链接随时打得开——这对求职演示不是加分项，是必选项。

排障实录2026-10-03

Celery on Windows 进程池崩溃排查实录

这个坑我在电商运营助手上连踩两次，第二次才彻底想明白。症状极具迷惑性，值得完整记录。

症状

Celery worker 日志一切正常：显示 ready、任务 received，但任务状态永远 PENDING，.get()一直超时。更诡异的是正常 worker 的日志里连 received 都没有——任务被什么东西截走了。

排查过程

  1. 先怀疑代码：任务体 import 同目录模块失败？改完依旧；
  2. 再看日志：满屏 SpawnPoolWorker-N 报 PermissionError(13, '拒绝访问。')——Windows 下 Celery 默认进程池必崩；
  3. 最阴的第三层：同名 worker 截胡任务。一台坏掉的 prefork worker 不退出，也能从 Redis 队列抢走任务却不执行，正常 worker 连任务都看不到。日志里 DuplicateNodenameWarning 是铁证。

解法

启动加 --pool=solo（Windows 没有 fork，prefork 生态不完整，solo 单进程最稳），并且多节点必须用 -n name@%h 唯一命名，从根上杜绝同名截胡。排查时用 celery inspect ping 看活了几台——注意是 inspect ping ，control 子命令里没有 ping。

附赠两个小坑：celery 不热重载，改 tasks.py 必须重启 worker；输出重定向到文件时 Python 块缓冲会让日志长期 0 字节，调试一律加 -u。现在这些经验都写进了项目的部署文档，换机器不再裸奔。

工程质量2026-10-17

用工具链守住「功能零改动」

融界工作台做深蓝科技风重设计时，我给自己立了条规矩：只改视觉层，app.js 依赖的 75 个元素 id、65 个 class 一个不删。口号容易，执行难——人都会手滑。所以先写工具，再动样式。

工具一：静态回归核对

一个 Python 脚本，把三份清单拉齐比对：JS 里引用的 id、HTML 里定义的 id、JS 模板动态注入的 id、JS 生成的 class、CSS 定义的 class、SVG 图标符号定义与引用。任何一边缺了另一边，直接报错退出。

# 核心逻辑（简化示意）
js_ids = set(re.findall(r'\$\("([\w-]+)"\)', app_js))
html_ids = set(re.findall(r'id="([\w-]+)"', index_html))
missing = js_ids - html_ids
if missing:
    sys.exit(f"缺失 id: {missing}")  # 改样式前先过这关

工具二：DOM mock 逻辑测试

静态核对只能证明「元素还在」，证明不了「点击还有反应」。用 Node 起一个最小 DOM mock（getElementById 返回可观测的假元素），eval 真实的 app.js，然后模拟点击、检查 toast 文案——18 项断言覆盖登录校验全路径。

执行纪律

  • 每轮改完：静态核对 → node --check → 逻辑测试，全绿才提交；
  • 每个阶段截图留证，前后对比；
  • 提交信息写清楚改了什么、验证了什么，回滚时找得到锚点。

这套流程的收益不只是这次重设计：后来加「六位随机验证码」功能，测试文件同步改断言，跑一遍 18/18 全绿就敢直接推送三端。回归从「凭记忆」变成「跑一遍」，这就是工程感和玩具Demo的分界线。
